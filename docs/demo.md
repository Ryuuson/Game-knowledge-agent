# 三分钟演示脚本

目标：展示从问题到本地证据、状态提示和边界处理。主演示只读离线检索，不生成模型结论，不写会话或笔记。真实聊天是单独的人工检查项，不能称整个应用完全离线。

## 开始前

在项目根目录、已安装依赖的环境中启动：

```powershell
.\scripts\run.ps1
```

打开 `http://127.0.0.1:8501`。启动脚本允许没有聊天配置或 BGE 索引的环境进入离线演示，只监听本机地址。

界面始终默认选择“离线检索演示”。聊天入口不可用不影响离线检索。选择 BM25 可在没有 BGE 模型／向量索引时使用现有 JSONL；BGE 需预先缓存模型并构建索引，首次构建可能联网下载，提前准备并预热，不计入三分钟。

## 现场操作

| 时间 | 操作 | 讲解与检查 |
| --- | --- | --- |
| 0:00–0:25 | 确认“离线检索演示”，选择“BM25 关键词检索”，展示片段数 3 | “这一步读取本机资料，展示原始片段；没有调用聊天模型。” |
| 0:25–1:15 | 查询“玩家在游戏后期金币越来越多，经济系统应该怎么设计回收机制？”并检索 | 展开“查看检索依据”，展示标题、来源编号、集合、章节与片段；状态应为“关键词候选”。说明须核对原文，不能将候选当作设计结论。 |
| 1:15–1:55 | 切到“BGE 语义检索”后重新检索 | 模型／索引可用则观察实际状态；不可用时检查“语义服务暂不可用，以下为关键词候选。”提示。主动选 BM25 与故障降级不同；两者均不能冒充高相关语义结果。 |
| 1:55–2:30 | 查询“智能硬件的固件升级失败，应该如何排查？” | 应显示“该问题明确属于其他行业，本地游戏资料不适用。”且无片段。这是拒绝套用游戏资料，并非具备硬件诊断能力。 |
| 2:30–3:00 | 回顾刚才的来源和状态 | “验证重点是证据是否相关、失败是否显式、边界是否清楚。聊天生成与回答质量还需单独验收。”不临时宣称准确率或性能提升。 |

若 BGE 正常，UI 不会凭空显示降级。需要稳定复现该分支时，提前在终端运行以下只读检查，现场展示结果；不删除或改名真实索引：

```powershell
@'
import json
from pathlib import Path
from wiki_corpus.retrieval import RetrievalService
paths = [Path('data/game_knowledge_chunks.jsonl'), Path('data/new_knowledge_chunks.jsonl')]
chunks = [json.loads(line) for p in paths for line in p.read_text(encoding='utf-8').splitlines() if line.strip()]
r = RetrievalService(mode='bge', chunks=chunks, vectors=None).search('玩家在游戏后期金币越来越多，经济系统应该怎么设计回收机制？', top_k=3)
print(r.status, r.fallback, r.reason, len(r.hits))
'@ | .\.venv\Scripts\python.exe -B -
```

上述模拟缺失索引检查输出为 `keyword_only True missing_index 3`；独立 BM25 检查返回 3 个候选、`fallback=False`，非游戏问题返回 `out_of_domain`、0 个候选。真实浏览器已验证 BGE 检索、来源展开和明确领域拒答，详见 [验证记录](verification.md)。界面报错时记录现象，不把失败说成演示成功。

## 真实聊天：待人工检查

本轮没有调用外部 API，以下完成前不得写“聊天已验证”。由用户按 README 完成模型配置，确认允许问题及必要上下文发送到对应远程接口，再切换“对话助手”：

1. 新建会话，发送“游戏角色技能的伤害与冷却如何搭配，避免唯一解？”。核对最终回答、来源编号和原文，区分事实与建议。
2. 追问“如果面向新手呢？”，检查上下文延续；刷新或切换会话，核对历史恢复及检索依据。离线演示无对话导出按钮。
3. 点击“导出对话与来源”，检查下载的 Markdown 是否包含最终回答、模式、状态与真实来源编号，记录模型和检查日期。
4. 另用长会话检查摘要不出现在最终回复；检查超长输入和服务不可用时的提示。失败如实记录，不用离线检索结果替代聊天验收。

关闭联网搜索只意味着不使用搜索适配器；聊天和摘要仍调用配置的模型 API。
