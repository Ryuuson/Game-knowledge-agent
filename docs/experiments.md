# 检索实验报告

2026-10-06，Windows / CPython 3.10.9，CPU 推理。评估有效完成：三条路径均未降级，运行前后语料、索引、代码和配置哈希一致。这里的“通过”表示实验正确执行，不表示全部案例检索正确。

完整逐案例记录见 [公开结果快照](../evals/reference_results/2026-10-06.json)。快照只将本机绝对路径替换为 `<PROJECT>`，保留原始数值、环境、哈希与候选编号；原始报告保存在本机 `.runtime/retrieval_evaluation.json`。

## 数据与方法

语料共 6,515 块、六个来源；SQLite 索引均为 `BAAI/bge-small-zh-v1.5`、512 维。40 条 AI 辅助构造回归案例中，30 条游戏正例每个来源各五条，共标注 41 个支持块；10 条非游戏问题单独计算拒答。程序核对了编号、原文证据和元数据的一致性。案例未经独立人工相关性审核，构造时可见语料，不能称为独立盲测。

比较 BGE 全量余弦扫描、BM25 词项检索、两者的 RRF 融合。Top-k 为 5；RRF 合并两路各 30 个候选，后续门限仍使用原始 BGE 余弦分数。原有 0.62 / 0.67 阈值保持不变，没有用本回归集调参。

排名路径 `apply_threshold=False` 保留领域规则，但关闭语义阈值；实际路径另调用 `apply_threshold=True`，允许筛选后补足候选，不能简单从排名结果删除若干项代替。BM25 没有语义阈值，其两组排名一致。任何 BGE／混合降级、模式变化或异常都会使整组结果失效，不用关键词结果冒充语义结果。

Recall@5 是每条正例前五个结果命中的标注块占该例全部标注块的比例，再宏平均；MRR 是首个标注块名次倒数的均值；nDCG 使用二元相关性；Hit@5 是至少命中一个标注块的正例比例。未标注块按不相关计，等价证据未穷举可能导致低估。所有排名均只以 30 条正例为分母，不能称为模型回答准确率。

## 实测结果

| 排名路径 | Recall@5 | MRR | nDCG@5 | Hit@5 |
| --- | ---: | ---: | ---: | ---: |
| BGE | 46.7% | 0.3944 | 0.4055 | 50.0% |
| BM25 | 70.0% | 0.6333 | 0.6395 | 73.3% |
| BGE + BM25 / RRF | 63.3% | 0.5594 | 0.5638 | 70.0% |

| 实际阈值路径 | Recall@5 | MRR | nDCG@5 | Hit@5 | 非游戏正确拒答 | 游戏误拒 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| BGE | 40.0% | 0.3444 | 0.3512 | 43.3% | 10/10 | 4/30 |
| BM25 | 70.0% | 0.6333 | 0.6395 | 73.3% | 8/10 | 0/30 |
| BGE + BM25 / RRF | 48.3% | 0.4344 | 0.4318 | 53.3% | 10/10 | 4/30 |

规则直接识别八个非游戏问题；余下两个在人事薪资和招生门户语境下仍获得词面候选。BGE 和混合的阈值挡住这两个问题，也拒绝了四个正常游戏问题：`wiki-economy-order`、`mechanics-gacha-pity`、`numeric-vfx-overdraw`、`senior-world-story`。这是召回与拒答之间的实际取舍，不能由 10/10 推断通用领域识别能力。

## 延迟和内存

| 策略 | 正例排名路径 p50 | p95 | 首次预热耗时 | 该策略结束时进程 RSS |
| --- | ---: | ---: | ---: | ---: |
| BGE | 16.55 ms | 18.15 ms | 22,001.95 ms | 522.8 MiB |
| BM25 | 15.75 ms | 19.49 ms | 1,423.70 ms | 607.4 MiB |
| 混合 | 51.17 ms | 65.53 ms | 1,520.62 ms | 621.4 MiB |

每条路径排除一次正例预热，固定案例顺序、每例执行一次排名查询和一次实际阈值查询，没有重复抽样或置信区间。表中的延迟为 30 条正例排名查询的服务计时，包含编码与检索，不含 UI、网络和聊天生成；不能当作端到端响应速度。

三条路径在同一进程依次执行并共享模型缓存。BGE 首次预热包含模型及索引加载，混合预热已复用模型，二者不能直接比较冷启动。RSS 用 Windows `GetProcessMemoryInfo` 测得，包含原生模型、索引与内存分配器；表中 BM25 的进程仍持有此前模型，不能说 BM25 独占 607.4 MiB。没有测 GPU、并发容量或各策略独立进程峰值。

## 失败案例与解释

| 案例 | 观察 | 可支持的判断 |
| --- | --- | --- |
| `base-texture-handoff` | BM25 的前两位均为标注的“引擎导入与命名规范”；BGE 返回项目管理、资产管线等附近主题；混合只在第四位命中一个标注块 | 精确技术词有助于词项匹配，融合可能降低原本很靠前的词项证据 |
| `numeric-aggro-taunt` | BGE 找到 `Aggro_System` 的其他块，却没有命中选定的两个编号；BM25 和混合各命中一个 | 应人工检查邻近块是否也能支持问题，不能把编号未命中直接当作内容完全错误 |
| `mechanics-gacha-pity` | 三条排名路径都没有命中标注块；BGE 和混合在阈值后无证据 | 长查询、英文机制资料与中文编码器的匹配可能是原因，但需要独立标注、查询分解和多语言模型对照才能确认 |
| `reject-payroll-unseen` / `reject-admissions-unseen` | BM25 仍返回候选，规则未识别该语境 | 词面检索和有限领域规则不能保证适用性，界面必须保留“候选”提示和原文核对入口 |

本轮保留 BGE 原有默认值及三种显式模式，没有根据这一个小样本切换全局默认或调低阈值。后续若继续研究，先增加独立人工相关性审核及等价证据，划分开发／保留集，再比较改进；重排序或更大模型属于待验证方案，本轮没有虚构其收益。

## 复现

准备现有 JSONL、本地缓存模型及匹配的 SQLite 索引后运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/evaluate_retrieval.py --backend all --top-k 5 --output .runtime/retrieval_evaluation.json
```

不加载 Agent 或 `.env`，不使用聊天 API。模型只从本地缓存加载，缺失时明确报失败。版本与哈希详见 JSON；关键指纹如下：

| 输入 | SHA-256 |
| --- | --- |
| 案例 | `3da57b77bc0c895fc952387d35b5f032b02ca9a8ef77469dcfb6ecc755433d4a` |
| 合并语料指纹 | `effb403859c155b368c72548251c4f8cbdc456975ba0abbe87ad3510722d26ef` |
| 配置及检索代码 | `0edd0c71fb8d132f29cef1ad0d345f1fd83594e75141f903d4f277994bbb1b27` |

结果只说明这个固定回归集和本机环境下的表现。系统引用编号、排序效果、模型事实支持和个人贡献是不同的验证对象；后两项分别见 [验证记录](verification.md) 与 [项目经历说明](project-experience.md)。
